# SplatStage : 전체 구조도

---

## 전체 구조

### 프로토타입 (로컬 PC)

모든 처리가 로컬 PC 한 대에서 실행된다.

```
┌──────────────────────────────────────────┐
│               로컬 PC                     │
│                                          │
│  브라우저 ←→ FastAPI                      │
│               │                          │
│               ▼                          │
│  프레임 추출 → SfM → 3DGS → .splat       │
│                                          │
│  SQLite (잡 상태)   로컬 폴더 (파일 저장)  │
└──────────────────────────────────────────┘
```

### 확장 (클라우드)

```
┌──────────┐    ┌──────────┐    ┌──────────────────┐    ┌──────────────┐
│  브라우저  │    │ FastAPI   │    │       S3         │    │  클라우드 GPU  │
│ (React)  │    │ (API서버) │    │                  │    │  (Docker)     │
│          │───►│ Presigned │───►│  input/          │    │               │
│          │    │ URL 발급  │    │  output/         │◄──►│  프레임 추출   │
│          │◄───│ 인증·API  │    │                  │    │  SfM          │
│          │    └──────────┘    └────────┬─────────┘    │  3DGS         │
│          │                            │              │  .splat 변환   │
│          │    ┌──────────┐    ┌───────▼──────────┐    │               │
│          │◄──►│    DB    │◄───│    Lambda        │───►│               │
│          │    │(Postgres)│    │ (GPU 시작 트리거) │    └──────────────┘
│          │    │ 잡 상태   │    └──────────────────┘
│          │    └──────────┘
└──────────┘
```

프로토타입에서 필요한 것 : FastAPI, SQLite, 로컬 폴더
확장에서 추가되는 것 : S3, Lambda, 클라우드 GPU, PostgreSQL, CDN

## 크로스커팅 설계

### Docker 전략

확장 시 파이프라인을 Docker 컨테이너로 구성한다.

- 목적 : 클라우드 GPU에 파이프라인을 올릴 때 "내 PC에서는 되는데 서버에서 안 됨" 문제를 방지
- 원칙 : 특정 플랫폼 전용 기능 사용 금지. 어디서든 docker run 하나로 동작해야 함
- 적용 시점 : 확장 단계에서 도입. 프로토타입에서는 로컬 환경에서 직접 실행

---

### 파이프라인

1. 영상 수신 및 입력 준비

   목적
   - 영상 파일을 수신하고 파이프라인에 전달
   - 모델이 바뀌어도 변하지 않는 공통 관문

   과정 (프로토타입)
   1. 브라우저가 영상 파일을 FastAPI에 올린다
   2. FastAPI는 파일을 임시 폴더에 저장한다
   3. FastAPI는 접수번호(job_id)를 즉시 반환하고 백그라운드에서 파이프라인을 시작한다
   4. 브라우저는 이 job_id로 5초마다 상태를 확인한다
   5. 저장된 영상 파일 경로를 다음 단계(전처리)에 넘긴다

   확장 시 전체 흐름
   1. 브라우저 → FastAPI : "영상 업로드하고 싶어"
   2. FastAPI → S3 : Presigned URL 요청
   3. FastAPI → 브라우저 : Presigned URL 전달
   4. FastAPI → DB : job 레코드 생성 (status: "uploading")
   5. 브라우저 → S3 : 영상 직접 업로드 (Presigned URL 사용)
   6. S3 업로드 완료 → S3 이벤트 발생 → Lambda 실행
   7. Lambda → DB : status를 "processing"으로 갱신
   8. Lambda → AWS API : GPU 인스턴스 시작
   → 이후는 2번(전처리) 흐름으로 이어짐
      (비동기) 브라우저 → DB : 5초마다 상태 폴링


2. 전처리 및 초기 구조 추출

   목적
   - 영상에서 프레임 추출, 포인트 클라우드·카메라 파라미터 생성
   - 3DGS 학습 입력물 생성. 실패 시 이후 전체가 무의미해지는 관문

   OUTPUT (다음 단계에 전달)
   - 포인트 클라우드 + 카메라 파라미터

   과정 (프로토타입)
   1. 이전 단계에서 영상 파일 경로를 넘겨받는다
   2. 영상에서 프레임을 추출한다
   3. 품질 낮은 프레임을 걸러낸다
   4. SfM을 실행하여 포인트 클라우드 + 카메라 파라미터를 생성한다
   5. 결과물을 다음 단계(Gaussian 생성)에 넘긴다

   확장 시 전체 흐름
   ※ 1번의 전체 흐름 이후, 클라우드 GPU 안에서 실행
   1. GPU → DB : status를 "preprocessing"으로 갱신
   2. GPU : 영상에서 프레임 추출 → 품질 필터링
   3. GPU → DB : status를 "sfm"으로 갱신
   4. GPU : SfM 실행 (포인트 클라우드 + 카메라 파라미터 생성)
   5-a. 성공 → 다음 단계(Gaussian 생성)로 진행
   5-b. 실패 → GPU → DB : "failed" + 에러 원인 기록 → GPU 종료
      (비동기) 브라우저가 폴링으로 "failed" 감지 → 실패 원인 + 재촬영 안내 표시


3. Gaussian 생성

   목적
   - 포인트 클라우드로 3DGS 학습, .splat 파일 생성
   - 파이프라인에서 GPU를 가장 많이 쓰고 가장 오래 걸리는 단계
   - [미결] 구현체 교체 가능한 인터페이스 설계 방식 결정 필요

   과정 (프로토타입)
   1. 3DGS 모델 실행 : 포인트 클라우드 + 카메라 파라미터 + 프레임 이미지 → .ply 출력
   2. 포맷 변환 : .ply → .splat
   3. 결과물을 다음 단계(결과물 전달)에 넘긴다

   확장 시 전체 흐름
   ※ 2번 완료 직후, 같은 GPU 인스턴스에서 이어진다.
   1. GPU → DB : status를 "gaussian"으로 갱신
   2. GPU : 3DGS 학습 → .ply → .splat 변환
      (비동기) 브라우저 → DB : 5초마다 상태 폴링
   3. GPU → S3 : .splat 업로드
   4. GPU → DB : "completed" + S3 경로 기록
   5. GPU → S3 : 원본 영상 삭제
   6. GPU 종료


4. 결과물 전달

   목적
   - .splat 파일을 브라우저에 전달, 파이프라인 진행 상황을 사용자에게 알림

   과정 (프로토타입)
   1. 파이프라인이 .splat을 로컬 폴더에 저장하고 SQLite에 완료 상태 기록
   2. 브라우저가 폴링으로 완료 감지
   3. 브라우저가 .splat을 받아 3D 뷰어에 렌더링

   확장 시 전체 흐름
   ※ 3번 완료 후 시작. GPU는 이미 종료된 상태.
   1. 브라우저가 폴링으로 DB에서 "completed" 감지
   2. 브라우저 → FastAPI : 결과물 다운로드 URL 요청
   3. FastAPI → S3 : Presigned URL 발급 (다운로드용)
   4. FastAPI → 브라우저 : Presigned URL 전달
   5. 브라우저 → S3 (CDN 경유) : .splat 직접 다운로드
   6. 브라우저 : 3D 뷰어에서 렌더링

---

### 웹

1. .splat 뷰어 + 씬 편집

   목적
   - .splat 배경 위에 3D 모델을 올려 씬을 구성하고, 원하는 구도로 스크린샷을 찍는 창작 도구
   - 모든 작업이 브라우저 안에서 완결됨

   과정 (프로토타입)
   1. 사용자가 .splat 파일을 업로드한다
   2. 브라우저가 .splat을 3D 공간으로 렌더링한다
   3. 사용자가 3D 모델(VRM·GLB·OBJ)을 업로드하여 씬에 배치한다
   4. 카메라 시점 이동·회전·줌으로 구도를 잡는다
   5. 씬 내 오브젝트를 이동·회전·크기 조정한다
   6. 현재 화면을 스크린샷으로 다운로드한다

   확장 시 전체 흐름
   ※ 확장1 기준 (공간 라이브러리 + 포즈 편집 포함)
   1. 사용자 → FastAPI : 로그인
   2. FastAPI → DB : 공간 라이브러리 목록 조회
   3. 브라우저 : 직접 .splat 업로드 또는 라이브러리에서 선택
   4. 브라우저 → S3 (CDN 경유) : 선택한 .splat 다운로드
   5. 브라우저 : .splat 렌더링
   6. 브라우저 : 3D 모델 업로드 → 씬 배치
   7. 브라우저 : 포즈 편집 (VRM 본 단위 조작)
   8. 브라우저 : 카메라·오브젝트 조작
   9. 브라우저 : 스크린샷 다운로드 또는 export

#### 기능 목록 (PRD 기준)

[프로토타입]
1. .splat 뷰어 - .splat 파일 업로드 후 웹에서 실시간 렌더링·시점 조작
2. 3D 모델 배치 - VRM·glTF·GLB·OBJ 업로드 후 씬 내 위치·회전 조작
3. 스크린샷 - 현재 화면 이미지 파일로 다운로드

[확장1]
1. 공간 선택 분기 - 직접 동영상 업로드(.splat 변환) 또는 라이브러리에서 선택
2. 전신 포즈 편집 - VRM 본(Bone) 단위 조작
3. 웹캠 표정·모션 캡처 - 실시간으로 VRM 모델에 반영
4. 기본 조명·쉐이더 - 배경과 모델의 이질감을 줄이는 최소한의 렌더링 요소
5. 결과물 export - Unity·Unreal 호환 확장자 및 OBS 삽입 가능 포맷

[확장2]
1. 자체 3DGS 파이프라인 - 자체 변환 모델로 교체
2. 물리 기반 조명 - 레이캐스팅·조명 지원
3. 애니메이션 - 키프레임 기반 모델 동작 생성
4. 자체 쉐이더 - 툰 쉐이더 등 기본 탑재 + 사용자 정의 쉐이더 업로드
